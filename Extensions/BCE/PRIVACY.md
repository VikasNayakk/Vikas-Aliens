# Privacy and data handling

## Active Microsoft Teams reader

- The Teams reader is **off until the owner turns it on**.
- When enabled, BCE monitors only the Teams groups the owner selected. It reads message content exposed in an open Teams browser tab: visible chat messages for the one-time last-five option and Teams in-app notification cards / visible message updates for live reading.
- BCE does not use Microsoft Graph, Entra app registration, Power Automate or a separate background Teams account connection. It cannot read a closed chat or a message that Teams does not expose in the open browser page / notification DOM.
- The extension checks that live message, audio-completion and status events originate from an allowed Teams tab and that the message belongs to a selected group.
- A new group is stored only when BCE can read its stable Teams conversation ID. Groups saved by older versions without that ID must be removed and added again once; BCE will not silently merge chats based only on display name.

## Data stored locally in Chrome

BCE uses `chrome.storage.local` for extension state. The current Teams reader may persist:

- Selected group names, normalized keys, stable conversation IDs, saved tab associations and priority order.
- The most recent eight accepted Teams message events, including sender and message text.
- Pending and currently active speech batches, including message text and audio references, so reading can continue after service-worker suspension.
- Processed-message identifiers (up to the configured cap). When Teams provides no stable message ID, BCE stores a SHA-256 fingerprint instead of embedding the message text in that identifier. Entries written by earlier versions may still contain text-based fallback keys until they are pruned by the cap or extension storage is cleared.
- Message counters, queue state, last status message and popup theme preference.

This local storage is **not encrypted by BCE**. Anyone who can access the browser profile or extension storage may be able to inspect it. Turning live reading OFF stops speech/audio and clears the pending/current speech queue, but it does not erase the selected groups, recent events or processed-message history. Removing a selected group removes its queued speech messages; it does not erase every previously stored event from that group.

## Speech and audio

- Spoken output is generated by Chrome's text-to-speech engine.
- Audio attachments are played only when the open Teams page exposes an audio player or a supported HTTPS / HTTPS-origin blob URL.
- BCE does not upload Teams messages merely to generate speech.

## Optional OpenAI analysis handler

The extension source retains an optional `ANALYZE_MESSAGES` handler:

- Without a saved API key, the handler uses local parsing.
- With a saved API key, explicitly submitted analysis text is sent to the OpenAI API. Pattern-based secret redaction is enabled unless the redaction setting is turned off; redaction is not infallible.
- The API key and model setting are stored in Chrome extension local storage. BCE does not encrypt the key.
- The current active toolbar popup / Teams reader does not automatically send monitored Teams messages to OpenAI. The analysis handler runs only when an extension UI or extension action explicitly invokes it.

## ChatGPT prompt scheduler

- Prompt jobs are created only from the BCE prompt manager and only for conversations the owner selects.
- BCE stores each job's prompt text, conversation ID, tab ID, repeat limit, sent / completed counters, status, send token, response baseline, timestamps and limited error details in `chrome.storage.local`. This storage is not encrypted by BCE.
- The ChatGPT content script enters the saved prompt into the selected conversation and clicks the page's Send control only when the composer and enabled Send button are found.
- Before sending, the content script captures local conversation counts and message identifiers. After sending, it requires a newly appended user-message record that matches the prompt. A send whose outcome cannot be verified is moved to manual review instead of being retried automatically.
- For response monitoring, message text stays in the ChatGPT page. The content script sends only message keys, counts, locally computed text fingerprints, response length and completion / uncertainty signals to the service worker. Full assistant response text is not saved in extension storage.
- Prompt text remains in the job record while it is retained in job history. The prompt is submitted through the signed-in ChatGPT website session in the selected browser tab; BCE does not send it through the optional OpenAI API analysis handler.
- A send or response that cannot be verified is marked for manual review. BCE does not automatically retry an uncertain send because doing so could duplicate work.
- Chrome extension local storage is accessible to the browser profile and is not an encrypted vault. Avoid storing passwords, access tokens or other secrets in prompts.

## ChatGPT and other browser workflows

- The prompt manager and controlled ChatGPT page adapter are part of the active manifest runtime. The old side-panel page and its read-only ChatGPT parser remain unregistered and inactive.
- Excel, Microsoft To Do, OneDrive, OneNote, Teams task classification, reusable workflow execution and automatic workflow creation are not currently implemented. Live ChatGPT UI behavior remains pending manual browser testing.

## Diagnostics and network use

- No telemetry, analytics or remote logging is implemented.
- Teams monitoring is browser-page based and requires the owner to keep a Teams tab open.
- The extension's optional analysis handler can contact `api.openai.com` only when explicitly invoked with a saved API key.
